# Explain Before Shorten

「短く書く」より先に、「相手に口頭でどう説明するか」を考える。
言葉だけを削るのではなく、扱う話題を整理して簡潔にする。

## 手順

1. **何を伝えたいかを一文で決める**
   - 仕組みの理解、違いの比較、判断理由の共有、手順の案内など、その説明の役割に合わせて「読み手に何を理解してほしいか」を一文で定める。
   - 読み手、目的、文体、長さの指定があればそれを優先する。

2. **まず、口頭ならどう説明するかを組み立てる**
   - いったん文字数を脇に置き、読み手が隣にいるつもりで「何がどうなるか」「なぜそうなるか」「どんな条件のときか」を具体的に組み立てる。
   - 「分離」「管理」「対応」「保証」などの抽象語だけで済ませず、実際の動きや条件で言い換える。
   - 確認済みの事実、推奨、可能性・仮説を区別する。

3. **違う話を分け、書く場所を揃える**
   - 仕組み、利用条件、例外、注意点を1つの文に詰め込まず、異なる話題は文を分ける。
   - 条件や制約は、対応する説明のすぐ近くに置く。
   - 重複する補足や主題から外れる話は削るか別の場所へ移し、重要な適用条件や制約は本文に残す。

4. **意味と条件を保って短くする**
   - 重複、不要な前置き、回りくどい修飾を削り、主体・対象・動作・因果関係・比較対象・重要な条件が読み取れる状態を保つ。
   - 「上限数は到達保証ではない」のような圧縮しすぎた表現を避け、一度読んで意味が通る表現にする。
   - 既存の用語・公式用語は維持し、必要なら初出で意味を補う。
   - 言葉を削るだけでは収まらない場合は、扱う話題を減らすか構成を見直す。
   - **肯定形と否定形を使い分ける**：
     - 行動を求める文は「何をするか」が分かる肯定形を基本にする（例：「設定を忘れないでください」→「設定を確認してください」）。
     - 禁止、危険の回避、例外、利用条件、できないこと、対比を正確に示す文では否定形を保つ（例：「この機能は使用しないでください」）。肯定形に直すと条件や意味の範囲が変わる場合は否定形のままにする。

5. **完成文だけで伝わるかを確かめる**
   - 完成した文章だけを読んで、「何の話で、何が起きるか」が分かるか確認する。
   - 隣り合う文を続けて読み、話題の飛躍や用語の揺れがないか確かめる。
   - 不自然さが残る場合は、単語の言い換えではなく 2 の「口頭ならどう説明するか」に戻る。
   - 短くしたことで重要な条件や意味が抜けていたら言葉を戻す。

## 書き換えの例

| 短くしすぎた表現 | 口頭でも説明しやすい文章 |
| --- | --- |
| 受付と完了確認を分離する | 処理の終了を待たずに受付済みと返し、結果は後から問い合わせる |
| 上限数は到達保証ではない | クォータなどの制約により、表の台数まで増やせない場合がある |
| 上限なしでも中断に備える | 実行時間を無制限にしても、サービス側の更新などで処理が止まることがある |

## 出力のしかた

- 通常の説明やファイル書き出しでは、検討過程（口頭説明の下書きなど）は出力せず、整えた完成文だけを出力・保存する。
- 文章の添削・書き換えを相談された場合は、完成文を先に示し、意味や構成を変えた要点だけを短く添える。
